# Harmony Forge Phase 2 Implementation Plan (post-MVP)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Превратить MVP (`v0.1.0-mvp`, master `9bc591e`) в продукт, готовый к внешним пользователям: закрыть review-follow-ups, включить измерение качества (§17), обучить первую настоящую модель, добавить аранжировку и дистрибуцию.

**Architecture:** Сначала стабилизация (устранение semantic drift + wiring настоящей модели), затем измерение (listening harness делает качество видимым), затем能力: настоящая генеративная модель → arrangement → дистрибуция; облако — последним и опционально. Каждый таск — независимо тестируемый инкремент на `master`; порядок отражает зависимости.

**Tech Stack:** CMake >= 3.22, C++20, JUCE 9.0.3 (vendored), Catch2 v3, ONNX Runtime 1.22.0, Python 3 + PyTorch (с Task 3), pluginval.

**Spec:** `docs/SPEC.md` (§§4.5, 9–11, 15, 17), `docs/superpowers/plans/2026-10-11-roadmap.md` (Task 6 + MVP traceability)

## Global Constraints

- `src/core` and `src/inference`: ZERO JUCE, pure C++20.
- NEVER allocate / lock / file I/O / inference in `processBlock`; UI/Inference→Audio only lock-free.
- Smart pointers, const-correctness; `std::optional`/status codes, no exceptions in critical paths.
- `ctest` after core/inference changes, both `HARMONY_FORGE_WITH_ONNX=ON` and `OFF` stay green.
- PPQ 480, pitch 0..127, velocity 1..127, lowercase scales, C3 = 60, tonic pitch-class-only, drums excluded from pitched analysis. C++20.
- Prior interfaces stable (ADD, never change): `GenParams`, `generate_candidates`, `rank_candidate`, `OnnxRunner`, `predict_async`/`try_take_completed`, `write_smf0/smf1`, `PatternDocument`, `TransportView`.
- pluginval strictness-5 stays SUCCESS; render seed-7 default hash `817FDB02…` stays identical (regression tripwire).

## Review Focus

- Длинная аранжировка (5 мин, смена секций каждые 8–16 тактов) — ожидается связная структура без зависших нот и дрейфа тональности, а не развал формы.
- Настоящая модель сhallucinates внеладовые пассажи в Strict — ожидается constraints-постобработка, режущая их до ≥0.90 compliance, а не пропуск мусора.
- Большой MIDI-корпус в parity/eval — ожидается проход без OOM и за разумное время, а не падение на 1001-м файле.
- Установщик на чистой Windows-машине — ожидается рабочий VST3 + DLL рядом, а не missing-onnxruntime-dll.
- Промпт «сделай темнее и проще» — ожидается детерминированное отображение в параметры движка, а не случайный результат при повторе.
