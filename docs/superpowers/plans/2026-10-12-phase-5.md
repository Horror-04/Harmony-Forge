# Harmony Forge Phase 5 Implementation Plan (reference import + Explain)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть два доказанных SPEC-пробела сценария «референс → анализ → объяснение»: загрузка MIDI-референса с разбором и вкладка Explain с теорией происходящего.

**Architecture:** Сначала продакшн-SMF-ридер в чистом core (парсер сейчас существует только как тест-хелпер), затем импорт референса в UI поверх готовых `detect_key`/`recognize_chord`, затем Explain поверх готовых `validate_voice_leading`/`classify_note`. Каждый таск — независимо тестируемый инкремент.

**Tech Stack:** CMake >= 3.22, C++20, JUCE 9.0.3, Catch2 v3, ONNX Runtime 1.22.0, pluginval.

**Spec:** `docs/SPEC.md` (сценарий §2 шаги 2–3: референс + анализ; §6 редактор; §12 вкладка Explain), `docs/TOKENIZATION.md`

## Global Constraints

- `src/core`: ZERO JUCE, pure C++20 (ридер — тоже). Smart pointers, const-correctness.
- `std::optional`/status, no exceptions in critical paths (парсер враждебных файлов — тем более).
- NEVER allocate / lock / file I/O / inference in `processBlock` (файловый ввод — только message thread).
- `ctest` both modes green; PPQ 480, pitch 0..127, velocity 1..127, lowercase scales, C3 = 60, tonic-pc, drums excluded. C++20.
- ADD-only (never change signatures); tripwires (suite green both modes, pluginval SUCCESS if plugin rebuilt, seed-7 hash identical) hold for every task.
- NEVER stage/commit unrelated files (explicit `git add` + `git status` every commit).

## Review Focus

- Битый/враждебный MIDI-файл — ожидается чистый отказ с понятным статусом, а не падение или UB.
- Референс в другом размере/PPQ — ожидается корректный пересчёт сетки, а не молчаливое искажение ритма.
- Анализ пустого или одноголосого референса — ожидается честный «недостаточно данных», а не выдуманная тональность с высокой уверенностью.
- Импорт с драм-картой GM — ожидается сохранение барабанов как Drums без попыток «гармонизовать» их.
- Explain при смене аккорда — ожидается пересчёт объяснений синхронно с ремонтом нот, а не устаревший текст.
