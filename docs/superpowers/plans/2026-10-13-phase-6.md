# Harmony Forge Phase 6 Implementation Plan (UX redesign, staged A+B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести редактор до accessibility-корректности и единой визуальной системы по UX-аудиту, не сломав поведение и tripwires.

**Architecture:** Stage A (доступность/корректность) идёт первым и мержится отдельно; Stage B (визуальная система) — только после A. Все правки — message thread, UI-слой; audio path, core/inference и генерация не трогаются. Тестирование GUI-логики — через GUI-free модели где возможно + build/pluginval/smoke.

**Tech Stack:** CMake >= 3.22, C++20, JUCE 9.0.3, Catch2 v3, ONNX Runtime 1.22.0, pluginval; ui-ux-pro-max skill — read-only reference (layout/UX copy), реализуем на JUCE сами, ничего из него не ставим/не запускаем.

**Spec:** `docs/superpowers/specs/2026-10-13-ux-redesign-design.md` (направление + A1–A5 + B1–B5 + non-goals)

## Global Constraints

- NEVER allocate / lock / file I/O / inference in `processBlock` (UI-правки его не касаются вообще).
- `src/core` + `src/inference`: ZERO JUCE, pure C++20 — эта фаза их не меняет, кроме случаев с явным разрешением в задаче.
- Smart pointers, const-correctness; `std::optional`/status, no exceptions in critical paths.
- `ctest` both modes green; PPQ 480, pitch 0..127, C3 = 60, tonic-pc, drums excluded. C++20.
- ADD-only + точечные правки (никакого редизайна раскладки; позиции вьюх сохраняются).
- Tripwires: suite green both modes; pluginval SUCCESS; seed-7 hash `8CECE0C2…AEE22` identical.
- NEVER stage/commit unrelated files (explicit `git add` + `git status` every commit).

## Review Focus

- Стрелки двигают ноты без мыши — ожидается тот же undo-шаг и те же snap/границы, что у drag.
- Tab-навигация по новому окну — ожидается видимый фокус на каждом контроле, без ловушек.
- Изменение размера окна вдвое — ожидается живая раскладка без налезаний и обрезанных подписей.
- Дальтоник-различение классов нот — ожидается cue помимо цвета (штриховка/контур/другое).
- Откат undo после keyboard-правки — ожидается ровно один шаг на жест, как у мыши.
