# Harmony Forge Phase 3 Implementation Plan (model quality)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Поднять качество настоящей модели: compliance-запас ≥0.95, новизна генераций, runtime-защита §10 в C++-пути, и подключить её в UI.

**Architecture:** Сначала измерение (eval-метрики, которые видят новизну, а не только prefix-compliance), затем данные (больше composed-корпуса), затем runtime-фильтр §10 в C++ (закрывает eval-only gap), затем UI-подключение модели (picker + async preview/export). Каждый таск — независимо тестируемый инкремент.

**Tech Stack:** CMake >= 3.22, C++20, JUCE 9.0.3, Catch2 v3, ONNX Runtime 1.22.0, Python 3.14 + PyTorch CPU, pluginval.

**Spec:** `docs/SPEC.md` (§§5.2, 10, 17), `docs/superpowers/plans/2026-10-11-phase-2.md` (Task 3/4 follow-ups), `training/MODEL_CARD.md`

## Global Constraints

- `src/core` + `src/inference`: ZERO JUCE, pure C++20. Smart pointers, const-correctness.
- `std::optional`/status, no exceptions in critical paths.
- NEVER allocate / lock / file I/O / inference in `processBlock`.
- `ctest` both modes green; PPQ 480, pitch 0..127, velocity 1..127, lowercase scales, C3 = 60, tonic-pc, drums excluded. C++20.
- Interfaces stable (ADD, never change): `GenParams`, `generate_candidates`, `OnnxRunner`, `predict_async`/`try_take_completed`, `AsyncGenerateQueue`, state props pattern.
- Tripwires: suite green both modes; pluginval SUCCESS if plugin rebuilt; seed-7 default hash identical UNLESS the task changes model weights (then re-prove determinism + record new hashes deliberately).
- Eval honesty rules (from Phase 2 rulings): no seed-tuning, no eval-sample cherry-picking, no threshold lowering; gates stay at their stated values.

## Review Focus

- Продолжение после редкого префикса — ожидается осмысленная новизна, а не копирование корпуса дословно.
- Runtime §10-фильтр на длинном verbatim-run — ожидается ранний стоп/замена, а не пропуск 48-оконного копирования.
- UI с выбранной моделью — ожидается отзывчивый интерфейс во время генерации, а не заморозка на ONNX.
- Повторная генерация с тем же seed после смены модели — ожидается детерминированный результат новой модели, а не смесь старой.
- Слабый composed-корпус — ожидается честный отчёт о качестве, а не подгонка цифр.
