# Harmony Forge Phase 4 Implementation Plan (landing + follow-ups)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Приземлить всё готовое (AGPL-merge, GPU-флаг), закрыть накопленные мелкие долги и оставить репозиторий в состоянии «чистый master, ноль известных дефектов».

**Architecture:** Строго по порядку зависимостей: сначала AGPL-rebase+merge (меняет заголовки везде — после него никакой кодовый diff не должен конфликтовать), затем GPU-флаг из shelved-WIP (только флаг, не веса), затем batch накопленных minors, затем медленный end-to-end тест. Человеческие шаги (repo, установка, FL, macOS) — отдельным чек-листом, не SDD.

**Tech Stack:** CMake >= 3.22, C++20, JUCE 9.0.3, Catch2 v3, ONNX Runtime 1.22.0, Python 3.14 + torch CPU/CUDA, pluginval.

**Spec:** `docs/SPEC.md`, `docs/DISTRIBUTION.md` (AGPL obligations), phase plans 2026-10-11-roadmap / 2026-10-11-phase-2 / 2026-10-12-phase-3

## Global Constraints

- `src/core` + `src/inference`: ZERO JUCE, pure C++20. Smart pointers, const-correctness.
- `std::optional`/status, no exceptions in critical paths.
- NEVER allocate / lock / file I/O / inference in `processBlock`.
- `ctest` both modes green; PPQ 480, pitch 0..127, C3 = 60, tonic-pc, drums excluded. C++20.
- ADD-only unless the task says otherwise; tripwires (suite green both modes, pluginval SUCCESS if plugin rebuilt, seed-7 hash identical) hold for every task.
- Eval honesty rules persist (no seed/sample/threshold gaming).
- NEVER stage/commit anything unrelated to the task at hand (explicit `git add` paths + `git status` check every commit).

## Review Focus

- Rebase AGPL поверх master — ожидается ноль потерянных заголовков и ноль конфликтов в логике, а не тихий дроп.
- GPU-флаг без весов — ожидается только код флага + smoke, а не протаскивание shelved-WIP весов в master.
- End-to-end тест с настоящей моделью — ожидается медленный/опциональный (не ломает быстрый `ctest`), а не +5 минут каждому прогону.
- Minor batch — ожидается ноль поведенческих изменений сверх перечисленных, а не расползание скоупа.
- Публичный репозиторий отсутствует — ожидается, что ничего не отгружается до его создания (повторный gate).
