# Harmony Forge Roadmap Implementation Plan (Sprints 1–5 + post-MVP)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести проект от готовой базы (Sprint 0, commit `922d8b9`) до MVP по `docs/SPEC.md` §14 за 5 последовательных спринтов.

**Architecture:** Contract-driven, снизу вверх: сначала чистый C++20 `src/core` (теория + MIR-анализ), затем токенизация и ONNX-инференс в фоне, затем constraints, затем JUCE-состояние/DAW-синк, затем UI. Каждый спринт — собираемый, тестируемый инкремент; следующий не начинается, пока не закрыт предыдущий.

**Tech Stack:** CMake >= 3.22, C++20, JUCE 9.0.3 (vendored), Catch2 v3, ONNX Runtime (со Спринта 2–3), Python 3 (токенизатор/экспорт), pluginval (со Спринта 4).

**Spec:** `docs/SPEC.md` (канон ТЗ), `docs/superpowers/specs/2026-10-11-project-base-design.md` (база), `docs/THREADING_MODEL.md`, `docs/TOKENIZATION.md`

## Global Constraints

- `src/core` must have ZERO dependencies on JUCE or GUI libraries. Pure standard C++20.
- NEVER allocate memory (`new`, `malloc`, `std::vector::push_back`) in the real-time audio thread (`processBlock`).
- NEVER lock mutexes (`std::mutex`, `juce::CriticalSection`) in `processBlock`.
- NEVER call file I/O, OS logging, or ONNX Runtime inference in `processBlock`.
- All communication between UI/Inference threads and Audio thread MUST use lock-free queues (`juce::AbstractFifo` or moodycamel::ReaderWriterQueue).
- Use standard smart pointers (`std::unique_ptr`, `std::shared_ptr`). No raw pointers for ownership.
- Const-correctness is strictly enforced.
- Error handling: Use `std::expected` (C++23) or `std::optional` / explicit status codes instead of throwing exceptions in critical paths.
- Always read `docs/SPEC.md` before implementing a feature.
- Run tests via `ctest` after modifying code in `src/core` or `src/inference`.
- PPQ tick = 480; pitch 0..127; velocity 1..127; scale names lowercase.
- C++ standard: 20 (`CMAKE_CXX_STANDARD 20`).
- Sequential gates: Sprint N+1 starts only when Sprint N meets its DoD below.

## Review Focus

- Референс-MIDI с пустыми тактами/перекрывающимися нотами на входе анализа — ожидается корректный разбор без падений, а не UB или исключение.
- Смена одного аккорда в прогрессии — ожидается правка только конфликтующих нот зависимых партий, а не перегенерация всего паттерна.
- Одинаковые параметры + seed при повторной генерации — ожидается бит-идентичный MIDI, а не «похожий» результат.
- Генерация во время воспроизведения в DAW — ожидается отсутствие зависаний и кликов, а не блокировка audio thread.
- Перетаскивание партии в FL Studio — ожидается валидный MIDI без артефактов (висячих note-on, обрезанных длительностей), а не битый файл.
