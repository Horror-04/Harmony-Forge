### B-0 — what was wrong (proven on identical input)

`Measure-Object -Line` on piped `git show` / `Get-Content` output counts only
NON-EMPTY strings — blank lines contribute 0, so it measured non-blank lines,
not physical lines (the Appendix A claim "`Measure-Object -Line` (= `wc -l`)"
was false):

- `git show HEAD:.../PluginEditor.cpp | Measure-Object -Line` → **975**;
  `(Get-Content ...).Count` → **1046**; Python `blob.count(b'\n')` → **1046**.
- Crafted proof: `@('', '', 'a', 'b') | Measure-Object -Line` → **2**.
- `PluginEditor.cpp` holds exactly 71 blank lines (1046 − 975 = 71 to the
  line); `PluginEditor.h` holds exactly 26 blank lines (324 − 298 = 26).
- Corrected method (this round only): Python `git show <sha>:<path>` blob
  bytes, `.count(b'\n')`. All blobs end in `\n`, so this = physical lines =
  `wc -l`. `Measure-Object -Line` on piped git output is banned from this task.
- Canonical-blob note: blobs are LF (`\r` count 0); worktree files are CRLF
  (autocrlf checkout). Newline COUNTS agree (324/1046 both), so counts are
  canonical either way; blobs used throughout.

**The D-B12 ceiling, and whether it is met.** The ceiling is on the Editor
TOTAL (`.h` + `.cpp`) at **≤1050** physical lines, with a **+5 %
record-with-reason tolerance**: 1050 × 1.05 = **1102.5**, so the measured
**1100 ≤ 1102.5** — the ceiling is met, with 2 lines of headroom, and the
tolerance is exercised (1100 > 1050, so the plain ceiling alone would NOT
have been met; the +5 % allowance is what carries it, and it is recorded
here with the reason the ruling itself gives: the layout is ~355 NLOC, so
the 1370 − ~350 ≈ 1020 estimate did not survive the real extraction, and
the tolerance replaced churn).

**PLAINLY STATED: this total ceiling is NOT machine-enforced.** The G1
file-size gate pins the individual FILES (`src/plugin/audio/PluginEditor.cpp`
at 807, and the 7 other pinned files), and the "set of files over 500 lines
must not grow" rule is a per-file rule. There is **no gate anywhere in this
repository that sums the Editor's lines across files** — so a 4-file Editor
at 1100 lines passes G1 with no total check at all. The ≤1050 total is an
OWNER-AGREED ACCEPTANCE CRITERION recorded in `docs/BACKLOG-phase-B.md`
(D-B12), not a gate: the 2-line headroom is a promise, not a ratchet, and
a future Editor change can push the total over 1050 without any tool
objecting. The per-file pins DO hold the growth: `PluginEditor.cpp` is
pinned at 807 and may not grow; `EditorLayout.cpp` (287) and
`EditorLayout.h` (141) are under 500 and are not pinned at all, so the
extracted unit can grow freely. The total is therefore the one number in
this table that nothing enforces — stated here so the next reader does not
mistake it for a gate.
